# 阶段 2A：前后端交易纵切片

## 目标

在不接入真实支付渠道的前提下，交付一条可以集成测试验证的交易链路：

```text
已发布商品 → 加入购物车 → 创建订单 → 预占 SKU 库存
→ 创建 Mock 支付 → 支付成功并确认库存
或支付失败/取消/超时并释放库存
```

## 默认决策

- 第一条纵切片只允许一个购物车和订单包含同一商家的 SKU；多商家拆单留到后续阶段。
- 购物车价格只用于展示，创建订单时由服务端重新读取 SKU 价格并计算总额。
- 创建待支付订单时立即从 `available_stock` 扣除预占数量，避免超卖；支付成功只确认预占，不重复扣减。
- 支付失败、用户取消或订单超时会释放预占并把数量退回 `available_stock`。
- 订单、支付和库存预占使用独立状态，不能用一个状态字段代替全部生命周期。
- 本地默认使用 `MockPaymentGateway`；真实渠道通过 `PaymentGateway` 接口接入。
- 订单创建、Mock 支付回调和 Outbox 事件都有幂等约束。
- 历史订单保存商品、SKU、价格、币种和收货地址快照，不随商品资料变化。

## 本纵切片包含

- 当前用户的购物车查询、设置 SKU 数量和删除条目。
- 从购物车创建单商家订单。
- SKU 悲观锁与库存预占。
- Mock 支付会话与成功、失败、取消结果模拟。
- 待支付订单主动取消与超时释放服务。
- 用户订单查询和商家订单查询。
- Nuxt 顾客端的 SKU 选择、购物袋、结算、订单列表和 Mock 支付操作。
- Vue 商家端的订单列表、支付/库存状态、收件快照和交易指标。
- `ORDER_CREATED`、`ORDER_PAID`、`ORDER_CANCELLED` Outbox 事件。

## 暂不包含

- 真实支付宝、微信支付、Stripe 或 PayPal。
- 优惠券、积分、促销、运费模板和税费。
- 多商家购物车拆单、合并支付和部分退款。
- 发货、物流跟踪、收货、售后和结算。
- 真实 AI 商品识别、推荐和向量检索。

## 验收场景

1. 未登录用户不能修改购物车或创建订单。
2. 未发布、已下架、禁用或无库存 SKU 不能加入购物车或下单。
3. 订单金额只按数据库当前价格计算。
4. 同一用户使用相同 `Idempotency-Key` 重试，只返回原订单。
5. 创建订单后库存立即预占，不能被第二张订单超卖。
6. 支付成功后订单为 `PAID`、支付为 `SUCCEEDED`、预占为 `CONFIRMED`。
7. 支付失败、取消或超时后库存只释放一次。
8. 重复 Mock 支付结果不会重复扣减或释放库存。
9. 用户只能读取自己的订单，商家只能读取包含自己商品的订单。
10. 订单状态变化与 Outbox 事件在同一事务提交。
11. 顾客端可完整走通“加购 → 结算 → Mock 支付”，且可售库存随预占结果变化。
12. 商家端能读取同一笔订单，且金额、支付状态、库存状态与顾客端一致。
