## 接口与事实边界

`POST /api/shop/v1/guide/messages` 的每条消息新增可选 `displayedProductIds`。仅助手消息可填写，按照该轮页面卡片实际顺序排列，最多三个唯一的正整数；用户消息只能为空。缺省按空列表处理，旧客户端仍可一般对话，但没有展示记录时不能确认“第二件”。原有角色、长度、CSRF、匿名本地预览及登录规则不变；响应未改动，没有数据库迁移。

前端不再把展示顺序拼进助手正文。字段只提供指代上下文，并不是经过服务端签名的历史凭证，也不代表价格、库存或购买权限。即使客户端伪造了历史 ID，服务端仍从当前公开目录读取商品，再执行预算、币种、规格、确认资料和可售校验。

内部意图新增 `reference`：`mode`、`assistantTurnIndex` 和 `position`。模型输入显式带 `turnIndex`；指向的助手消息索引为0基，卡片位置为1基。服务端不从自然语言正文解析商品 ID。

| 模式 | 服务端行为 |
| --- | --- |
| NONE | 没有历史指代，或明确改换商品类别；沿用一般检索 |
| EXACT | 只核对指定一款，基于当前已确认资料返回简短说明和卡片，不再由回复模型重新选品 |
| REFINE | 指定款新增必须条件；候选限于该款，仍由证据回复判断未结构化性能要求 |
| CHEAPER | 同一类目 ID、同币种、排除原款；按当前 SKU 价格严格筛选比原款当前起价低的替代 |
| CHEAPER_REFINE | 同类低价比较同时新增必须性能；仍进行证据回复，不将未验证防水等商品当作满足条件 |
| AMBIGUOUS | 清空位置并追问，不猜某款，不返回卡片 |

歧义、缺少记录、位置不在展示列表内时，服务端追问。指定款下架、不符合新条件或资料版本改变时，不能用别的商品冒充。模型返回未知候选 ID 时，撤回整段模型回复与卡片，包括未知 ID 出现在三张有效卡片之后的情况。回复模型没有加购、订单或支付工具。

低价比较使用 `BigDecimal`，候选预算为用户预算与原款当前起价减0.01的较小值；最终重新读取原款与候选，并校验版本、币种、类目和现价。它比较的是当前起价，不是历史已选 SKU 的成交价；同类目不等于功能或性能相同。未来多 SKU 比价需要独立的规格锚点，不复用这项有限定义。
