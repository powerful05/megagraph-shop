## 资料契约

既有商家草稿 PATCH 增加可选 `supplyDetails`：颜色、面料成分、版型、季节、场景、测量方法、图片来源声明，以及 SKU 对应的成衣尺码表。尺码表使用厘米和 `BigDecimal`，胸围与衣长必填，肩宽和袖长可缺失；同一个 SKU 不能重复，不能引用其他商品的 SKU。图片来源是商家的声明，不代表平台已核实版权或图片与实物一致。

资料与商品存储在同一版本的 `product` 记录中，新增迁移 V7，历史迁移不改写。修改资料沿用已有流程：先下架、保存草稿、重新确认，再发布。草稿更新清除旧确认时间。省略或传入空 `supplyDetails` 保留已有资料；改变 SKU 编码时必须同步更新尺码对应关系。旧商品仍可读取和发布，但资料缺失会明确呈现，不能由模型猜测。

商家与公开商品响应增加 `evidence`：商品版本、商家 ID/名称、实物交付类型、资料来源、确认状态、确认时间和结构化资料。确认状态区分 `MISSING`、`UNCONFIRMED`、`MERCHANT_CONFIRMED` 和 `TEST_CONFIRMED`；数据来源区分 `MERCHANT` 和 `LOCAL_TEST`，不由客户端决定。`PHYSICAL` 仅表示本阶段实物交付，不提供数字权益或服务预约的可售资格。

模型候选携带服务端提供的资料。商品返回前再次检查公开可售资格和版本；调用期间改版或下架时撤回旧结果，提示重新核对。页面把模型建议和可核查的商品资料分开展示，详情打开时重新获取当前商品；这些控制不等于模型自由文本已通过逐句事实核验或推荐质量评测。

```bash
GUIDE_TEST_SUPPLY=true bash apps/backend/scripts/run-guide-local.sh
NUXT_API_UPSTREAM=http://127.0.0.1:8081 pnpm --filter @megagraph/shopper-web dev --port 3001 --host 127.0.0.1
MERCHANT_API_UPSTREAM=http://127.0.0.1:8081 pnpm --filter @megagraph/merchant-web dev --port 5174 --host 127.0.0.1
```

仅同时启用 `local,supply-demo` 才加载或对顾客开放测试供给。两家测试商家、三个测试实物商品沿用上传存储、SKU、草稿确认、发布和 Outbox 路径。各商品的 M 尺码具有不同成衣测量值；价格、库存、属性与尺寸全是测试设定，图片复用已有 AI 生成素材。再次启动不覆盖现有测试商品。关闭该 profile 后，即便知道 ID，公开目录、图片和购物车入口也不能访问测试商品。

工作台在已登录的本地示例商家账号下可切换测试商家，补资料、下架及重新确认。测试商品不代表真实商家参与，不构成真实供给验收；生成图片不证明面料或尺寸。
