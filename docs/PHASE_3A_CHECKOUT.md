# 3A 跨商家购物车与试用子订单

2026-10-01：在商品资料契约与本地测试供给之后，实现跨商家购物车、下单组和独立的试用子订单。当前仅开放本地/测试 Mock 环境，不构成真实收款、履约或阶段整体验收。

## 冻结契约

购物车可包含多个商家的实物 SKU，当前只支持 CNY。`POST /api/shop/v1/checkouts` 使用既有收货信息请求体和 `Idempotency-Key`，返回 `id`、`groupNo`、币种、服务端重算总额、创建时间和 `orders` 子订单列表。`GET /api/shop/v1/checkouts/{groupId}` 只允许所属用户读取当前子订单状态。金额、商家和 SKU 来源仍由服务端决定。

同一用户的购物车修改与提交使用购物车行锁串行化，提交按 SKU ID 升序锁定库存。下单组按商家生成一个子订单，每个子订单独立拥有原有支付单、库存预占、订单状态与 Outbox 事件。创建整组是一个数据库事务：任何一家的 SKU 失效或库存不足，整组、所有子订单、库存和创建事件都回滚，购物车不清空。成功后按组清空已提交条目，重复同一幂等键返回已有下单组；同一键但收货信息不同返回 `CHECKOUT_IDEMPOTENCY_CONFLICT`。幂等键不用于自动重新下单，修改购物车或收货信息视为新的用户意图。

组只保存创建时总额，不承担共享支付终态。支付、取消、到期与 Mock 售后都在子订单层处理；一家支付失败只能释放该家的预占，不回滚其他已成功子订单。旧 `/orders` 创建接口保留单商家兼容行为，消费者新结算页使用 `/checkouts`。

新增迁移 V8：下单组表与用户级幂等唯一约束、订单下单组外键、`test_order`，以及订单项商品版本和属性/尺码 JSON 快照。历史迁移不修改。订单读取契约增加 `checkoutGroupId`、`testOrder`；订单项增加 `productVersion` 和 `supplyDetails`，历史订单允许缺失这两项快照。

## 试用与页面状态

新下单组的所有子订单标记为试用订单；包含本地测试商品的旧接口订单也标记为试用。商家端显示试用标识、下单组与独立子订单状态，试用订单不计入成交金额或成交数量，不能创建物流或发货记录。Mock 支付和退款不代表真实收款或退款，当前不存在真实结算渠道。

购物袋和结算页按商家分组显示条目与预估金额；订单页分别展示各子订单的支付和库存状态及下单资料快照。前端同一次失败重试保留幂等键，成功后或用户改变购物车/收货信息后更新。真实支付、数字权益、服务预约和跨币种结算未开放。

## 验证范围

验收覆盖多商家购物车、整组创建、重复/并发同键提交、异址同键冲突、跨用户访问隔离、第二家创建失败回滚、第一家支付成功而第二家失败、库存独立释放与试用订单发货阻断。继续沿用单订单的过期、取消、支付事件和 Mock 退款测试。

已完成根目录 `pnpm verify`：58 项后端测试中 55 项通过，3 项 MySQL 专项因未配置隔离测试库跳过；双前端类型检查、生产构建和后端打包通过。新增 4 项跨商家集成测试覆盖上述幂等、隔离、回滚和支付失败场景。日志中的预期唯一约束冲突和 V6 迁移拒绝来自既有负向测试，不是测试失败。

浏览器使用本地 H2、明确标注的测试商家 A/B 和测试商品完成两家同车结算，生成同组两个子订单。A 灰色开衫 Mock 支付成功、库存 `CONFIRMED`；B 米白针织上衣 Mock 支付失败、库存 `RELEASED`，目录显示该商品库存恢复而 A 保持扣减。订单保留下单资料版本 3/7，不以最新商品资料覆盖快照。

真实 MySQL 的迁移/锁/并发行为仍需独立测试库验证，H2 不替代该验收。真实商家供给和推荐质量评测仍未完成；未合入主分支或推送。
