# 3B 真实 AI 导购：检索、证据与对话加购

2026-10-01：用户确认按“3A 收尾 → 3B 真实导购”顺序推进。本轮交付第一个可评测纵切片，不代表真实用户试用或完整 3B 验收。

## 本轮冻结范围

顾客仍从空白对话和底部输入框开始，不要求填写标准商品名称。模型先从多轮用户描述提取购买意图，再由 Java 服务按已发布、可售的公开目录筛选，最后让模型基于当前候选回复或追问。对话结果可打开当前商品详情、选规格和加入购物袋，沿用既有跨商家 Mock 拆单。

意图是内部结构，不改变浏览器对话请求。字段包括交付类型、明确的单件预算上限和币种、检索词、明确商品类别词、必要/排除颜色与材质、用户明确要求的尺码和是否需要先澄清用途。只有模糊心情而未说明用途时先追问，不将服饰库存当作用户意图。后续用户改口覆盖已撤销约束；助手历史不能产生用户没有提出的硬约束。历史助手消息附上当轮展示的 ID/标题顺序，供理解“第二件”等指代，不保存旧价格/库存为可售依据。场景和风格只影响排序，不作为材质、尺寸或穿搭适配的事实。

检索从完整公开目录筛选后截取最多 50 个候选，不能先取最新 50 件再过滤。类别同时匹配商品标题和已有可见类目路径，“上衣”不能漏掉该类目中的衬衫或开衫。预算与尺码在 SKU 层判断，候选只携带符合条件的 SKU；颜色、材质等硬要求只使用已确认资料，缺失即不能证明满足。数字商品和服务暂无交易供给，返回空商品列表和需求讨论，不混入衣服。

模型不得执行 SQL 或改变价格、库存、发布、订单和支付。推荐返回前再查当前目录、商品资料版本和本次约束，资料失效时撤回旧结论；未知 ID 不能成为商品卡片。商品详情与加入购物袋分别重新读取/校验现时可售事实。尺寸讨论仍须区分成衣尺寸与人体尺寸，不承诺合身。

## 运行与评测

一次对话最多两次模型调用：意图提取与证据回复。默认每次 HTTP 连接 5 秒、读取 25 秒，关闭 SDK 自动重试；页面保留显式重试，单轮前端超时 75 秒。日志只记录请求标识、阶段、模型、耗时、token 用量和失败类别，不记录聊天、商品资料、地址或密钥。token 数不等于费用，未配置价格表前不声称有准确成本金额。

固定问题集覆盖场景、追问、多轮改口、硬预算、颜色排除、材质、尺码、缺失资料、无结果和虚拟/服务边界。自动化测试验证结构化解析与服务端约束；真实模型跑同一套自然语言问题，记录商品选择和人工阅读结论。Mock 测试不替代真实模型质量证据。

## 非目标与验收边界

继续使用明确标注的测试商家、测试资料和生成图片，没有真实商家资料不阻断开发。真实供给、真实用户反馈和导购质量统计仍是阶段验收条件。暂不引入向量/图数据库、持久 Agent 图、3D、真实支付、数字权益或服务预约。

3A 新增迁移与跨商家并发需在 MySQL 8.4 的独立空库验证，现有数据不得重置。预览分支交付与合入主分支是不同操作，本轮不自动合入或推送。
