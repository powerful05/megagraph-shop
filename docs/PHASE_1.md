# 阶段 1：商品入库与发布闭环

## 目标

阶段 1 交付一条可验证的垂直链路，而不是完整商城：

```text
图片上传 → 入库任务 → 商品草稿 → 商家补齐必填项 → 确认 → 发布
→ 用户端查询已发布且有库存的商品 → 商家下架 → 用户端立即不可见
```

## 本阶段默认决策

- MySQL 是商品、SKU、价格、库存和发布状态的唯一事实源；本地测试使用兼容模式 H2。
- 商品不保存总库存；库存只存在 `product_sku.available_stock`。
- AI 先使用可替换的 Mock 生成器，避免外部模型阻塞业务状态机验证。
- 上传图片先使用可替换的本地文件存储；数据库只保存对象键与元数据。
- 发布必须经过服务端校验，不能依赖前端按钮状态。
- 商家数据通过登录用户的 `merchant_user` 关系隔离，不接受客户端指定任意 `merchant_id`。
- 发布与 Outbox 事件在同一个数据库事务中提交。
- 用户端每次查询都从事实库检查发布状态、商家状态和 SKU 可售库存。
- 商家工作台使用 Vue SPA；用户端/品牌官网使用 Nuxt，为后续 SSR、SEO、动态叙事和 3D 留出空间。

## 暂不包含

- 真实视觉模型、OCR 和文案模型。
- MinIO 适配器、Neo4j、Milvus、Redis。
- 自然语言推荐和推荐反馈。
- 订单、购物车、支付和履约。
- 生产级品牌首页 3D 动效。

## 验收场景

1. 相同 `Idempotency-Key` 重试上传，不重复创建商品。
2. 商家 A 不能读取或修改商家 B 的草稿。
3. 草稿缺少类目、标题、图片、SKU、价格或可售库存时不能发布。
4. 旧版本提交返回冲突，不能覆盖新版本。
5. 发布和 Outbox 事件同时成功。
6. 用户端只返回已发布、未删除、商家有效且至少一个 SKU 有库存的商品。
7. 商品下架后用户端立即不可见。
