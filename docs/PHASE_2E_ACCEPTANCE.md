# 阶段 2E 验收记录

记录日期：2026-09-26。状态：**2E 实现与验收完成**，由 Lead 从独立集成分支合入 `main`。范围以 [PHASE_2E.md](PHASE_2E.md) 为准；2E 完成不表示真实用户 AI 购物试用已经可以开放。

## 已落地

- V6 新增规范化用户名唯一约束、一次性邀请码和 JDBC Session 表；迁移在持久 DDL 前检查旧用户名规范化碰撞。未修改 V1–V5。
- 邀请制顾客注册、服务端 Session 登录/恢复/退出、CSRF、登录/注册限流和试用 profile 隔离；浏览器不再发送 Basic 凭据。
- 商家业务请求必须显式选择 `X-Merchant-Id`，后端按账号、成员关系、商家状态和角色逐请求授权；公开商品限定活跃商家的已发布内容。
- 两个前端经同源 `/api` 使用会话，商家端切店清理旧数据；顾客首页提供跨商家统一对话输入骨架，明确提示 AI 尚未开放。
- 非 Mock 环境只可选品和维护购物袋；能力接口返回 `mockPaymentAvailable=false`，后端拒绝新订单，避免页面隐藏按钮后仍可预占库存。

## 已知限制与后续边界

- 登录/注册限流按单实例内存和远端 IP 计数。反向代理可能把多个用户聚合到同一 IP；对外试用前必须确定可信客户端地址与共享/网关限流策略，不能把当前限流当作多实例方案。
- V6 对旧用户名的规范化碰撞先行拒绝迁移。MySQL 失败迁移仍可能留下 Flyway 失败记录；应由操作者核对冲突并处理迁移记录，不自动重命名账号或清理业务数据。
- 开发期间的中间测试 schema 不复用为正式基线；验收只依据上表最终 schema。保留测试数据，没有删除用户数据库。
- 统一对话入口是诚实标注的骨架，没有真实推荐。跨商家购物袋、拆单及受控试用 Mock 环境属于 3A；真实模型导购与评测属于 3B。未引入真实支付、AI 或对象存储凭据。
- 后续先冻结 3A 契约，而不是直接开放公网试用或开始真实支付。
