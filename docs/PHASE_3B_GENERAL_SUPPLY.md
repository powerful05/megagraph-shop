## 契约

`SupplyDetails` 新增 `profile` 和 `specifications`，商品资料与订单快照均返回这些字段。没有 profile 的旧 JSON 按 `APPAREL` 读取，缺少 specifications 按空列表读取；旧成衣资料、确认版本和旧订单保持兼容。数据仍存于既有 TEXT JSON 列，没有新增或重写数据库迁移。

- `APPAREL`：保留版型、季节、测量声明及 SKU 成衣尺码表；不能同时填通用规格。
- `GENERAL_PHYSICAL`：保留颜色、材质、适用场景、图片来源与可选规格说明；版型必须为空、成衣尺码表必须为空。`fabric` 为兼容保留字段名，通用实物界面显示“材质”。
- 通用规格每行包含 `skuCode/name/value`，最多30行；只能引用本商品 SKU，同 SKU 的规格名不可重复，每个 SKU 至少一行。修改 SKU 编码必须同步修改资料，不可留下孤立行。
- 资料 JSON 编码后限制60000字节，防止在 H2 可写但超出 MySQL TEXT 容量。修改、确认、发布和 Outbox 沿用业务事务。

商家可选择资料类型并编辑规格项；消费者详情按资料类型展示。通用实物不会出现胸围、衣长或人体合身提示。该 profile 只说明资料结构，不表示虚拟商品或服务具备可售资格。
